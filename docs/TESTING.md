# Как проверить систему

Есть три уровня проверки. Начните с первого: он не требует ни домена, ни Telegram.

---

## 1. На ноутбуке в браузере (10 минут)

Нужно: установленный **Docker Desktop** (запущенный) и **Git**.

```bash
git clone https://github.com/almosistore-droid/Umar-beekeeping.git
cd Umar-beekeeping
docker compose -f docker-compose.dev.yml up --build
```

Первый запуск занимает 3–5 минут: скачиваются образы и пакеты. Готово, когда в логах появилось
`Local: http://localhost:5173/`. Это окно не закрывайте.

**Во втором окне терминала** (в той же папке):

```bash
# демо-данные: 2 пасеки, 10 ульев, 10 маток
docker compose -f docker-compose.dev.yml exec backend python -m app.utils.seed --telegram-id 111111

# строка для входа (действует 7 дней)
docker compose -f docker-compose.dev.yml exec backend python -m app.utils.dev_init_data 111111 --first-name Умар
```

Откройте **http://localhost:5173**. Появится экран «Откройте в Telegram», а под ним — блок
«🧪 Вход для проверки на компьютере». Вставьте туда строку из второй команды и нажмите «Войти».
Вы войдёте как администратор.

> Совет: в Chrome нажмите F12 → значок телефона (Ctrl+Shift+M) и выберите iPhone — так вы увидите
> приложение в размере телефона.

Этот блок входа есть **только** в режиме проверки. На боевом сервере его нет. Строка
подписывается токеном бота и проверяется сервером так же, как настоящий вход из Telegram.

**Документация API (Swagger):** http://localhost:8000/api/docs

**Остановить:** `Ctrl+C` в первом окне. Данные сохраняются до следующего запуска.
Начать с чистой базы: `docker compose -f docker-compose.dev.yml down -v`

## 2. Что проверить (чек-лист этапов 1–7)

### Вход и роли
- [ ] Вход работает, на главной ваше имя и роль «Администратор».
- [ ] «Ещё» → «Пользователи»: войдите во второй вкладке браузера (режим инкогнито) с другим ID:
      `... dev_init_data 222222 --first-name Помощник`. Новый пользователь появится в списке
      как «Наблюдатель». Он видит ульи, но не видит кнопок «＋ Улей», «Заменить матку» и т. д.
- [ ] Поменяйте ему роль на «Помощник» → он может менять силу семьи, но не создавать ульи.

### Пасеки и ульи
- [ ] «Ещё» → «Пасеки» → «＋ Пасека»: создайте пасеку, кнопкой 📍 подставьте координаты.
- [ ] «Ульи» → «＋ Улей»: создайте улей с семьёй.
- [ ] Попробуйте создать второй улей с тем же номером на той же пасеке → понятная ошибка.
- [ ] Дата установки в будущем → ошибка «не может быть в будущем».
- [ ] Фильтры «Сильные», «Слабые», «Без матки», поиск по номеру и по коду матки.

### Матки
- [ ] «Матки» → «＋ Матка»: дата рождения 15.06.2024 → возраст считается сам («2 года 3 месяца»),
      цвет метки подставляется автоматически.
- [ ] Год рождения в будущем, неверная оценка → ошибки на русском.
- [ ] В карточке улья «Подсадить матку» → матка появилась, в «Истории» запись.
- [ ] «Заменить матку» на другую → у старой статус «Заменена», в истории «M-105 → M-205».
- [ ] Перенос матки в другой улей → прежний улей становится «Без матки».
- [ ] «Убрать» матку со статусом «Погибла» → её нельзя подсадить снова.

### История не теряется
- [ ] Измените номер улья (✏️) → адрес страницы (UUID) тот же, в истории «Изменён номер».
- [ ] «Сменить семью» → во вкладке «Семьи» видны обе: старая закрыта, новая активна.
- [ ] Статус улья «Продан» → улей ушёл в «Архив», его семья и матка отмечены проданными,
      вся история осталась.

### Этап 3: осмотры, болезни, обработки, подкормки
- [ ] Обновите демо-данные: `docker compose -f docker-compose.dev.yml exec backend python -m app.utils.seed --telegram-id ВАШ_ID` — добавятся осмотры, варроатоз с обработками, подкормки.
- [ ] Улей → «Осмотр»: рамки подставились из прошлого осмотра; выберите силу, «Матка: видна» → «Сохранить осмотр». В карточке обновились сила, дата последнего и следующего осмотра.
- [ ] Поставьте рамок с мёдом больше, чем всего рамок → кнопка не сохраняет, внизу красное предупреждение.
- [ ] Осмотр с «Матка: не найдена» и «Яйца: нет» → после сохранения предупреждение «возможно, без матки».
- [ ] «Болезнь» → Варроатоз, «Подтверждено» → статус улья «Болеет». Американский гнилец → «Карантин».
- [ ] «Лечение» → выберите болезнь, препарат, «Повторная обработка: через 7 дн.» → болезнь перешла в «Лечение», в карточке появилось напоминание.
- [ ] «Подкормка» → сахарный сироп 2 л → запись в «Хронологии».
- [ ] В карточке болезни «Вылечено» → улей снова «Активный».
- [ ] Главная: плитки «Требуют осмотра» (открывает отфильтрованный список ульев) и «Напоминания» (список с кнопкой «Готово»).
- [ ] Под ролью «Наблюдатель» кнопки осмотра, лечения и подкормки неактивны.

### Этап 4: мёд, продукция, операции с семьями
- [ ] Снова выполните команду `seed`: появятся откачки мёда за два сезона, воск и прополис, прошлая зимовка, отводок (улей №11) и кочёвка улья №7 на горную пасеку.
- [ ] Улей → «Мёд»: вес 12,5, цена 80 → под ценой «Сумма: 1 000». Сохраните — в карточке появится «Мёд 2026».
- [ ] «Ещё → Мёд»: итог за год, в среднем на улей, за всё время, график по месяцам (нажмите на столбец — покажет кг; «Таблица» — точные числа), рейтинг ульев.
- [ ] Главная: плитка «кг мёда за год» и лучший улей.
- [ ] «Операции → Переместить» на другую пасеку. Если номер там занят — система попросит новый.
- [ ] «Отводок» в новый улей без матки → открывается новый улей «Без матки», семья «Отводок»; в хронологии обоих ульев видна связь.
- [ ] «Объединить» два улья, оставив матку второго → второй улей в архиве «Объединён», у первого матка из второго.
- [ ] «Роение» → пойман → новый улей → у нового улья семья «Рой».
- [ ] «Зимовка» → начать; затем снова «Зимовка» → «Погибла» → улей стал пустым, семья и матка отмечены погибшими.
- [ ] «Ещё → Продукция» → записать воск 1,2 кг по 150.

### Этап 5: QR-коды, сканер, открытие улья по ссылке
- [ ] Улей → карточка «QR-код улья» → откроется большой QR, номер улья и ссылка `https://t.me/ваш_бот?startapp=hive_…`.
      Если вместо ссылки жёлтое предупреждение «Бот не указан» — впишите `TELEGRAM_BOT_USERNAME` в `.env` (см. раздел 3, шаг 5).
- [ ] Измените номер улья, подсадите другую матку, переместите улей → QR и ссылка те же.
- [ ] В браузере «Скачать PDF» → файл с наклейкой. «Ещё → QR-наклейки»: выберите пасеку, добавьте 2 пустые наклейки →
      «Скачать PDF» → в файле наклейки всех ульев по номерам и 2 «Новый улей», по 12 на листе A4.
- [ ] Печатайте на A4 **в масштабе 100%** (не «по размеру страницы»).
- [ ] В истории улья запись «Напечатан QR-код», в карточке «Напечатан 1 р.».
- [ ] «Сканер» на компьютере: вставьте ссылку из карточки → откроется улей. Вставьте `hello` → «Это не QR-код улья».
- [ ] Внутри Telegram на телефоне: кнопка «Сканер» сразу открывает камеру → наведите на QR (с экрана ноутбука или
      с распечатки) → открывается нужный улей.
- [ ] В Telegram «Отправить PDF в чат» → бот присылает PDF в чат. Перешлите его на компьютер и распечатайте.
- [ ] Отсканируйте пустую наклейку → «Улей не найден» → «Зарегистрировать улей с этим QR» → создайте улей №40 →
      повторное сканирование той же наклейки открывает улей №40.
- [ ] Отсканируйте QR **обычной камерой телефона** (не из приложения) → Telegram откроет приложение сразу на этом улье.
- [ ] После сканирования открывается выбор **«Осмотр» / «Проверка»**.
- [ ] «Осмотр»: всё выбирается кнопками, данные прошлого осмотра уже подставлены — можно сразу «Сохранить осмотр».
      Кнопка «Вчера» записывает осмотр вчерашним днём. После сохранения — «Следующий улей» сразу открывает сканер.
- [ ] Паспорт улья → вкладка «Осмотры»: каждый осмотр отдельной записью со своей датой.
- [ ] «Проверка»: вверху итог «Всё в порядке» / «Требует внимания» / «Есть проблемы» и причины
      (нет матки, мало корма, признаки роения, просрочен осмотр, болезнь…), ниже — семья, матка, последний осмотр, мёд.
      Проверка ничего не записывает.
- [ ] Под ролью «Наблюдатель» «Осмотр» неактивен, «Проверка» работает. QR виден, но кнопок печати нет; «Улей не найден» — без кнопки регистрации.

### Этап 6: главная со статистикой и годовой отчёт
- [ ] Главная: плитки (ульи, требуют осмотра, напоминания, сильные/слабые, больные, без матки, матки), мёд за год,
      полоса «Доход / Расход / Прибыль — этап 7». Нажатие на «Слабые семьи» открывает отфильтрованный список ульев.
- [ ] Графики: мёд по месяцам (нажмите на столбец — покажет кг; «Таблица» — точные числа), мёд по ульям,
      сила семей, болезни за год, возраст маток.
- [ ] «Отчёты»: выберите год. Разделы «Ульи» (на начало года, сейчас/на конец, новые, потерянные, проданные,
      объединённые, отводки), «Матки» (средний возраст, лучшие семьи), «Мёд» (лучший и худший улей),
      «Болезни» (случаи, вылечено, препараты), «Финансы» (стоимость продукции).
- [ ] Продайте улей или объедините два — в отчёте за текущий год изменятся «Проданы» / «Объединены» и «Сейчас».
- [ ] «Выгрузить отчёт»: PDF, Excel, CSV. В браузере — «Скачать», в Telegram — «Отправить в чат» (бот пришлёт файл).
      Excel: листы «Сводка», «Мёд по ульям», «Мёд по месяцам», «Болезни». CSV открывается в Excel без «кракозябр».

### Этап 7: CRM — клиенты, заказы, продажи, долги, расходы, прибыль
- [ ] Обновите демо-данные командой `seed` — появятся клиенты, расходы за год, продажи с долгами и заказы.
- [ ] Внизу вместо «Матки» кнопка **CRM** (у администратора и пчеловода). Матки — в «Ещё». Под ролью «Помощник» CRM не видна.
- [ ] CRM: прибыль за месяц или год, доход, расход, получено денег, долги, мёд на складе; графики по месяцам и категориям.
- [ ] «＋ Продажа»: клиент (или «＋ Новый клиент» прямо в форме), мёд 10 кг по 100 → «Итого 1 000».
      «Частично» 300 → «Останется долг 700». Сохраните — продажа появится в «Долгах».
- [ ] «Долги» → «Принять» → сумма уже подставлена → долг исчезает. Оплата больше долга — понятная ошибка.
- [ ] «＋ Заказ» → «Собран» → «Выдать заказ» (можно в долг) → заказ стал продажей.
- [ ] «＋ Расход»: категория, сумма, на что. Нажмите на расход — можно исправить или отменить (с причиной).
- [ ] Клиент: «Позвонить», куплено / оплачено / долг, покупки и заказы, «Убрать в архив».
- [ ] Главная: строка «Доход / Расход / Прибыль» и графики доходов и расходов. «Отчёты» → раздел «Финансы», он же в PDF, Excel и CSV.
- [ ] Отменённая продажа или расход не считаются в суммах, но видны в истории.

### Админ-панель (только администратор)
- [ ] «Ещё → Админ-панель»: пользователи по ролям, сколько заходили за 7 дней, все записи по разделам
      (пасека, здоровье, мёд и операции, CRM), состояние системы (бот, QR-ссылки, база, часовой пояс, валюта).
- [ ] «Пользователи и доступ» → «＋ Добавить» → по @username (или Telegram ID), роль «Помощник», «Кто это» →
      «Добавить» → «Отправить приглашение» (откроется выбор чата в Telegram). Человек открывает бота →
      сразу «Помощник», а не «Наблюдатель». Приглашение исчезает из «Ждут первого входа».
- [ ] Добавьте того, кто уже пользуется приложением → роль меняется сразу.
- [ ] «Отозвать» приглашение → человек входит наблюдателем.
- [ ] Снимите галочку «Доступ разрешён» → у человека «Учётная запись отключена».
- [ ] «Журнал действий»: все изменения по всей системе, фильтр по пользователю и разделу, «Показать ещё».

### Два языка: русский и тоҷикӣ
- [ ] «Ещё → Язык · Забон» → «Тоҷикӣ»: приложение перезагружается, все экраны, кнопки и ошибки на таджикском
      (буквы ӣ ӯ ҳ қ ҷ ғ отображаются нормально, без квадратиков).
- [ ] Закройте и откройте мини-апп (и на другом устройстве) → язык сохранился.
- [ ] Ваши данные (названия пасек, клиенты, заметки) не переводятся — остаются как вы их ввели.
- [ ] «Отчёты» → PDF, Excel и CSV на таджикском; QR-этикетки — «Куттии №…».
- [ ] Боту `/start` с таджикским языком Telegram → ответ на таджикском. Новый пользователь с языком Telegram
      «tg» сразу видит таджикский.
- [ ] Обратно «Русский» → всё снова по-русски.

### Приложение на телефоне (без Telegram)
Нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` в `.env` и запуск с `--profile telegram` (вместе с туннелем
запускается бот). Адрес — строка `TUNNEL URL` в логах туннеля.
- [ ] Откройте адрес туннеля в Safari (iPhone) или Chrome (Android) → экран «Войти через Telegram».
- [ ] Нажмите кнопку → открывается бот → «✅ Войти» → вернитесь в браузер: открывается главная, ваш аккаунт и роль.
- [ ] «Поделиться → На экран «Домой»» (iPhone) или «Установить» (Android) → значок Fayzi Umar → открывается без входа.
- [ ] «Сканер» → разрешите камеру → наведите на QR-наклейку улья → открывается «Что делаем с ульем?».
- [ ] В боте нажмите «Отмена» вместо «Войти» → в приложении «Вход отменён в Telegram».
- [ ] «Ещё → Выйти на этом устройстве» → снова экран входа. Админ блокирует пользователя → на телефоне экран входа
      с «Учётная запись отключена».
- [ ] «Журнал действий» в админ-панели: запись «вошёл в приложение на телефоне» с названием устройства.
Адрес туннеля меняется после сна ноутбука — тогда значок нужно установить заново; на сервере адрес постоянный.

### Вход по логину и паролю (без Telegram)
- [ ] Админ: «Пользователи → ＋ Добавить → Логин и пароль» → имя, логин, роль «Помощник» → «Создать вход» →
      виден временный пароль, «Отправить человеку» открывает отправку текста.
- [ ] В браузере телефона (или в другом браузере) на экране входа: логин + временный пароль → «Придумайте свой
      пароль» → новый пароль дважды → открывается главная с ролью «Помощник».
- [ ] Неверный пароль → «Неверный логин или пароль»; 5 раз подряд → «Слишком много неудачных попыток».
- [ ] «Ещё → Сменить пароль» работает; «Ещё → Выйти на этом устройстве» → снова экран входа.
- [ ] Админ нажимает «Новый пароль» у человека → на его телефоне снова экран входа, старый пароль не подходит.
- [ ] У человека без Telegram в «Отчётах» только «Скачать», без «Отправить в чат».

### Этап 8: напоминания в Telegram
- [ ] «Ещё → Напоминания в Telegram» → «Прислать пробное сообщение» → в чате с ботом «🔔 Уведомления Fayzi Umar работают».
- [ ] Запишите обработку улья со «следующей обработкой» на сегодня → в течение 5 минут (с 7:00 до 21:00) бот пишет
      «💊 Сегодня: …», кнопка «Открыть улей» открывает этот улей. Повторно то же напоминание не приходит.
- [ ] Улей с просроченным осмотром → «🔍 Напоминание. Улей №… давно не осматривался. Последний осмотр: …».
- [ ] Продажа в долг → «💰 Долг клиента …» приходит администратору и пчеловоду, помощнику — нет.
- [ ] Выключите «CRM» в «Ещё» → о долгах больше не пишет; у наблюдателя напоминаний нет совсем.
- [ ] Язык Тоҷикӣ → напоминания приходят на таджикском.

### Одновременное редактирование
- [ ] Откройте редактирование одного улья в двух вкладках, сохраните в первой, затем во второй →
      «Улей уже изменил другой пользователь».

## 3. Внутри Telegram на телефоне (с ноутбука)

Telegram открывает Mini App только по **HTTPS-адресу из интернета**. Для проверки без сервера
подойдёт бесплатный временный туннель Cloudflare.

1. Впишите в файл `.env` (в корне проекта; создайте из `.env.example`) **настоящий** токен бота и
   свой Telegram ID:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   ADMIN_TELEGRAM_IDS=ваш_id
   ```
   и перезапустите: `docker compose -f docker-compose.dev.yml up --build`
2. Запустите систему вместе с туннелем (вместо обычной команды):
   ```bash
   docker compose -f docker-compose.dev.yml --profile telegram up -d --build
   ```
3. **Ничего вставлять в @BotFather не нужно.** Туннель сам ставит свой адрес на кнопку «Пасека» в боте
   (через токен из `.env`). Если адрес умирает (ночью, после сна ноутбука), через ~2 минуты туннель
   сам создаёт новый и снова обновляет кнопку. Посмотреть текущий адрес:
   ```bash
   docker compose -f docker-compose.dev.yml logs tunnel | findstr "TUNNEL MENU"
   ```
   (на Mac/Linux вместо `findstr` — `grep`). В логе будет `TUNNEL URL: https://…` и `MENU BUTTON OK -> https://…`.
4. Откройте бота на телефоне и нажмите кнопку «Пасека» → приложение откроется внутри Telegram,
   вход произойдёт автоматически. Если Telegram показывает старое — закройте и снова откройте чат с ботом.

5. **Для QR-кодов (этап 5).** Впишите в `.env` имя бота без `@`:
   ```
   TELEGRAM_BOT_USERNAME=имя_вашего_бота
   ```
   В **@BotFather** → `/mybots` → ваш бот → **Bot Settings → Configure Mini App → Enable Mini App** и отправьте
   тот же адрес туннеля. Тогда ссылка `https://t.me/имя_бота?startapp=hive_…` из QR открывает приложение сразу на улье.
   Перезапустите: `docker compose -f docker-compose.dev.yml --profile telegram up -d`.
   *(Вариант: создать отдельную Mini App командой `/newapp` и вписать её короткое имя в `TELEGRAM_WEBAPP_SHORT_NAME`.)*
   Кнопку меню туннель обновляет сам, а адрес в **Configure Mini App** Telegram через бота менять не даёт —
   при смене адреса туннеля обновите его там вручную, если проверяете QR обычной камерой телефона
   (сканер внутри приложения работает и без этого). QR-коды при этом **не меняются** — в них только имя бота
   и номер улья, а не адрес сервера.

Адрес туннеля меняется при каждом запуске `cloudflared`. Для постоянной работы нужен сервер с
доменом (см. README → «Установка на сервер»).

## Если что-то не работает

| Проблема | Что сделать |
|---|---|
| `Cannot connect to the Docker daemon` | Запустите Docker Desktop и подождите, пока он загрузится |
| Порт 5173, 8000 или 5432 занят | Закройте другую программу или перезагрузите компьютер |
| «Не удалось войти: signature is invalid» | Строку входа нужно сгенерировать заново после смены токена в `.env` |
| «initData has expired» | Сгенерируйте новую строку (действует 7 дней) |
| «Не удаётся открыть страницу», ERR_NAME_NOT_RESOLVED | Временный адрес туннеля умер. Подождите 2–3 минуты — туннель создаст новый и обновит кнопку сам; затем закройте и откройте чат с ботом. Быстрее: `docker compose -f docker-compose.dev.yml restart tunnel` |
| В Telegram «Bad gateway 502» | Туннель работает, а приложение нет: проверьте, открывается ли http://localhost:5173. Запускайте туннель через `--profile telegram`, а не отдельно |
| Белый экран | `docker compose -f docker-compose.dev.yml logs frontend --tail=50` |
| Ошибки сервера | `docker compose -f docker-compose.dev.yml logs backend --tail=50` |

Пришлите вывод логов или скриншот — разберёмся.
